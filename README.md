# Menu OS — قائمة رقمية عبر QR

نظام قائمة رقمية للمطاعم والكافيهات: لوحة إدارة + قائمة عميل + طلب واتساب + QR.

## التشغيل محليًا

```bash
npm install
npm run dev
```

هيفتح المشروع على `http://localhost:5173` تقريبًا.

## البناء للنشر

```bash
npm run build
```

هيطلعلك مجلد `dist/` جاهز ترفعه على أي استضافة (Vercel, Netlify, Cloudflare Pages...).

## هيكل المشروع

```
src/
  lib/
    id.js            مولّد معرّفات فريدة
    image.js          تصغير الصور قبل التخزين
    storage.js         طبقة التخزين (راجع الملاحظة تحت)
    defaultData.js      البيانات الافتراضية وإعدادات الـ slug
  components/
    shared/           مكوّنات عامة (Field, ImageUploadField, Toast, RoleSwitch)
    admin/            كل تبويبات لوحة الإدارة (بيانات المطعم، الأقسام، المنتجات، العروض، QR)
    customer/         قائمة العميل (هيدر، عروض، أقسام، منتجات، سلة)
  App.jsx             المكوّن الرئيسي اللي بيربط كل حاجة
  index.css           كل التصميم والألوان والخطوط
  main.jsx            نقطة الدخول
```

## ⚠️ قبل ما تبيع الخدمة لمطاعم حقيقية

المشروع دلوقتي بيستخدم تخزين مبسّط (`src/lib/storage.js`) يشتغل بـ `localStorage`
على جهاز المستخدم. ده تمام للتجربة والعرض، لكنه **مش كافي للإنتاج** لأن:

- كل عميل بيفتح الرابط من متصفح/جهاز مختلف مش هيشوف نفس بيانات المطعم
- مفيش تسجيل دخول، يعني أي حد يعرف الـ slug يقدر يعدّل بيانات المطعم

**عشان تجهزها فعليًا للبيع:**
1. اعمل Backend بسيط (Node/Express أو أي framework تفضّله) + قاعدة بيانات
   (Postgres/MongoDB) يحفظ فيها كل مطعم بياناته
2. استبدل الدوال جوه `src/lib/storage.js` بنداءات `fetch` لسيرفرك، مع الحفاظ
   على نفس الأسماء (`storageGet`, `storageSet`) عشان باقي الكود يفضل شغال زي ما هو
3. ضيف نظام تسجيل دخول لكل مطعم (Email/Password أو Magic Link)
4. لو عايز صور بجودة عالية وعدد أكبر، استخدم خدمة تخزين صور (Cloudinary, S3,
   Supabase Storage) بدل تخزين الصورة كـ base64 جوه بيانات المطعم
5. اضبط `DEMO_DOMAIN` في `src/lib/defaultData.js` على الدومين الحقيقي بتاعك
   عشان روابط الـ QR تشتغل صح
